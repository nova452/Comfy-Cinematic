# Browser-only storage — status and handoff

Comfy Cinematic can be hosted publicly. Each visitor brings their own Comfy
Router key and their own render targets, and everything they make (projects,
renders, uploads, settings) lives in **their browser**. The server is stateless:
it proxies one model call per request and keeps nothing.

Build, types and tests are green: `tsc --noEmit`, `next build`, and
`node --test test/*.test.ts`.

---

## How it works

```
localStorage "cinematic.settings"       the key, targets, prompt model, local model names
        │  base64 JSON in `x-comfy-studio` on every API call
        ▼
Next routes  ── read per request, never stored ──▶  Comfy Router / ComfyUI
        ▲
        │  generated bytes come back inline (data URL)
IndexedDB "comfy-cinematic"
  projects   name, frames, chat, library
  media      one blob per still, clip or track
```

- `lib/studio-settings.ts` — the header codec (pure, tested).
- `lib/client-settings.ts` — `readSettings` / `rememberAccount` / `apiFetch` and friends.
- `lib/browser-db.ts`, `lib/browser-projects.ts`, `lib/browser-media.ts` — IndexedDB.
  A `src` is `media:<uuid>.<ext>`; `mediaUrl()` resolves it to an object URL and
  `useMediaVersion()` re-renders when a blob lands.
- `lib/account.ts` — `readAccount(request)`, `routerKey(request)`, `isAllowedEndpoint`,
  `envRouterKey` / `envLocalKey`, `redirectMode`.
- `lib/router.ts` — `runModel(apiKey, …)`, which pins the key to one call (the SDK's
  `comfy` namespace is process-wide).
- `lib/media-data.ts` — `dataUrl(bytes, type)`, what a render route answers with.

`PUBLIC_HOSTING=1` marks a shared deployment: the host's own `COMFY_API_KEY` /
`COMFY_LOCAL_API_KEY` are never lent out, and a render target that resolves to a
private or loopback address is refused (the dialog says so at save time).

## Done

- [x] Removed `.data/` and `lib/store.ts`; deleted `api/projects`, `api/renders`,
      `api/local-model` (GET/PUT) and `api/local-image` (GET/PUT).
- [x] `api/account` is stateless: GET reads the header and returns a masked tail + balance,
      POST validates new settings (including `fetchBalance`) and hands back `saved`.
- [x] `api/harness` and `api/video` answer with data URLs; the page stores the bytes.
- [x] Verify routes read the visitor's settings; `redirect: "manual"` under `PUBLIC_HOSTING`.
- [x] Settings, projects and media all live in the browser; the account menu, the H3 gear
      and the FLUX gear write to `localStorage`.
- [x] CSP + `X-Frame-Options` + `Referrer-Policy` in `next.config.ts`; `next start` binds
      all interfaces.
- [x] Tests: header codec, stored-account validation, hosted-mode keys, private-address
      checks, request-scoped account reads.

## Still open

- [ ] **Export / import.** Clearing site data deletes everything, and the only copy is the
      browser. A zip of `projects` + `media` + the settings (without the key) is the
      obvious next step. This is now the biggest gap.
- [ ] **Share links** (`/p/<id>`) only resolve in the creator's browser. Relabel or remove
      "Copy link" until there is a backend to share through.
- [ ] **Rate limits** on `/api/harness` and `/api/video` per IP (the key is the visitor's,
      but CPU and bandwidth are the host's).
- [ ] **Comfy Desktop on a hosted site** is the server's `127.0.0.1`, not the visitor's.
      Either hide the option under `PUBLIC_HOSTING` or document a tunnel.
- [ ] **Optional "remember this key"** toggle (`sessionStorage` when off).
- [ ] A Dockerfile and a short "Deploy" section in the README (Docker/VPS/Fly — the host
      must allow 300 s and 840 s requests, so not a hobby serverless tier).
- [ ] Consider deduplicating stored reference images: a render that uses the same
      reference twice stores it twice today.
- [ ] One-time import of an old `.data/` folder, for anyone upgrading a local install.
